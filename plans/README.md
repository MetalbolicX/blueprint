## Findings considered and rejected (round 2026-07-20)

- **ARCH-01** (DenoShell.execFileAsync Liskov violation): **rejected — false
  positive**. `DenoShell.execFileAsyncRaw` correctly uses `Deno.Command.make`
  directly without `sh -c`; only `execAsyncRaw` (the shell-interpretation
  path, matching Node `exec` semantics) wraps in `sh -c`. The audit's reading
  was incorrect and was rejected after orchestrator verification.
- **STRUCT-13** (split PromptResolver.res, 535 lines, into PromptEval +
  PromptValidation + orchestrator): **rejected — disproportionate ROI**. The
  file is large but internally well-structured with clear sequential
  responsibilities; splitting adds module hops without proportional clarity.
  Live with the size; revisit only if responsibilities further diverge.
- **STRUCT-15** (split Manifest.res, 348 lines, into ManifestTypes +
  ManifestJson): **rejected — disproportionate ROI**. Same reasoning as
  STRUCT-13; the parse function is long but the file is cohesive.
- **QUAL-07 / QUAL-08** (O(n²) Array.concat in reduce; redundant
  `makeHelpersDict()` per render): **rejected — noise at realistic scale**.
  Generators rarely exceed 50 templates; the constant factor is trivial.
- **QUAL-11** (Obj.magic at EJS boundary in render path): **rejected — safe
  interop**. The casts land at untyped JS data with no runtime risk; typed
  EJS bindings would be cleaner but not worth a separate plan.
- **QUAL-12** (sequential shell command execution in ShellExecutor): **rejected
  — correct default**. Commands may have ordering dependencies; the existing
  plan 012 already parallelized independent file writes.
- **Strategy pattern for ConflictResolver, Builder pattern for Config**:
  **rejected — over-engineering for a 7.6k LOC CLI**. The current if/switch
  on resolution type (5 cases) and flat Config record load are the right
  shapes; patterns would add indirection without removing complexity.
